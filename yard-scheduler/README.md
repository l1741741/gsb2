# 货场调度演练 (yard-scheduler)

一个原创的、可本地运行的浏览器调度演练:用时间表给几台搬运车分配路段,
目标是在截止时隙前把所有货物送到月台。TypeScript 实现,无运行时依赖。

## 运行

```sh
npm install        # 仅开发依赖 typescript / @types/node
npm run build      # 编译到 dist/
npm start          # 在 4399 端口起静态服务
```

打开 <http://localhost:4399/> 即可游玩。`npm test` 运行模拟核心的单元测试。

## 玩法

1. 顶部选择场景,左侧是地图,下方是占用时间线,右侧是车辆计划与运行控制。
2. 选中车辆后可改**起步时隙**,或点"点选编辑路线"后在地图上点击节点追加路段;
   "删除末段"可回退路线。虚线样式的路段是已经走过的锁定前缀,不可改写。
3. "运行 / 单步 / 跑到时隙 / 跑到结束"用于试跑;随时可以暂停。
4. 发生冲突(死锁 / 超时 / 计划错误)后,在冲突卡片上点"回退到 t=N",
   或在时间线上点击过去的某个时隙,即可回到那一时刻修改计划再跑。
5. "保存到浏览器 / 导出 JSON"会记录初始地图、初始计划和全部修改记录;
   读取 / 导入后从 0 重放同一过程到存档时隙。

## 规则模型

- 时间是离散整数时隙(tick)。所有占用区间都是**半开区间** `[开始, 结束)`:
  同一时隙离开与进入互不冲突,月台车位也可以首尾相接。
- 地图 = 节点(货场 / 岔口 / 月台)+ 通道(单向或双向、宽或窄)+ 出发车。
  - 窄路段:双向合计同时只允许一台车;宽路段:每个方向最多两台。
  - 节点有等待车位上限(货场 4、岔口默认 1、巷口 0、月台不允许停留)。
  - 月台有卸货车位数;车辆进入末段前须先预约到 `[到达, 到达+卸货)` 的车位。
- 车辆到达节点但下一路段被占、且节点等待车位已满时,会**滞留在原路段上**
  (占用延长)——这是窄巷死锁的来源。
- 结算考虑:路段占用冲突、对向相遇(窄路段双向互斥)、同时抢同一月台车位。
  死锁通过"等待-占用图"上的环判定,冲突会定位到具体车辆与所在路段/节点。
- 模拟完全确定:同时隙内车辆按编号顺序行动,不依赖随机数与墙钟。
  因此同一计划以任何显示速度运行,结果都相同;存档重放亦复现同一过程。

## 编辑约束(暂停在时隙 t 时)

- 已送达 / 卸货中的车辆完全冻结,防止货物重复送达;
- 起步时隙仅未起步车辆可改,且必须大于当前时隙;
- 路线只能重写未走过的后缀,已走过的前缀(含正在行驶的路段)锁定,
  车辆不会瞬移。

## 内置场景

- **basic**:三台车、两座单车位月台、一条窄路段。默认计划即可全部按时送达,
  用来熟悉让行、月台争抢与占用时间线。
- **alley**:两段窄巷串联、巷口不能停车。默认计划在 t=8 死锁(V1、V2 互相
  等待);回退到 V2 起步前,把它的起步时隙推迟到 12 之后即可通过。

## 目录结构

```
src/model.ts        地图与计划的数据模型
src/sim.ts          确定性离散时隙模拟器(结算核心)
src/scenarios.ts    内置场景
src/persistence.ts  编辑规则、存档格式与确定性重放
src/main.ts         浏览器 UI(画布、时间线、计划编辑)
tests/sim.test.ts   模拟核心单元测试(node --test)
```
